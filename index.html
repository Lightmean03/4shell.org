Every *4Shell and *2Shell, in one place.

Since Log4Shell in 2021, the internet has named its worst remote-code-execution bugs after it. This site tracks each one, with links to the CVE records at NIST NVD, CISA's Known Exploited Vulnerabilities catalog, vendor advisories, technical write-ups and public proof-of-concepts.

About

Why "4Shell" and "2Shell"?

Log4Shell (December 2021) took its name from "Log4j" plus "shell": one log line gave an attacker a shell. Spring4Shell and Text4Shell followed in 2022. In December 2025, React2Shell switched to "2Shell" ("React to shell"), and the 2026 wave of PHP2Shell, Node2Shell, wp2shell and others kept that form. Most of these names are informal, so always check the CVE IDs.

What gets listed

A bug is listed when it has a CVE, is widely called *4Shell or *2Shell, and has been covered by at least one reputable source. Related "-Shell" bugs that don't follow the naming (ProxyShell, ToolShell, Shellshock) are out of scope.

About the PoC links

Proof-of-concept links point to third-party code that hasn't been audited. Fake "PoC" repos that install malware show up within hours of every big CVE. Read the code before you run it, run it only in an isolated lab, and test only systems you're authorized to test.

Contribute

Found a new one, a dead link, or a better PoC? Every entry lives in data/vulns.json. Open a pull request or an issue on GitHub.
